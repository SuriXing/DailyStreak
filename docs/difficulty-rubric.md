# 难度分级 rubric（1–4 级：按"学生要做多少工作"判）

`content/subject-banks/difficulty.json` 顶上的 `_rubric` 是这套分级的原文，也是下面所有判据的基准：

> 难度分级（1-4），按"学生实际要做多少工作"判定，不按知识点：1 = 一条定义/公式/事实即可定案，
> 无中间判断；2 = 两个标准步骤（先算再读、先代入再解释）；3 = 三步以上，或两步但含真实陷阱
> （越界/重载/移位/条件必须先查/常见错误干扰项）；4 = 需要洞察或重构（多条件同时成立、
> 必须自己选择方法）。标注由代理按此 rubric 逐题判定，我抽查分布与个例；这是 rubric 判定而非实测校准。

这份文档把四个等级各自"照着判"的判据、每一级的真实例子、判级时最容易犯的错、以及改级的完整流程
写下来，目的是让下一道题的级别可以被第二个人**独立复算**，而不是只能相信标注者的说法。

## 这是什么判定

**是"预期工作量"，不是"实测难度"。** 题库里 900 道带选项的题（640 张练习册 + 260 张情境题）
每道都有 1–4 的标注，但没有人答过这些题、也没有任何答题记录，所以级别说的是"这道题要求考生
做多少步工作、要不要自己找方法"，不是"多少学生答错"。两族（练习册、情境题）由两批互不通气的
评审分别标注，这也是 README 里两族分布可以放在一起比较的前提。

AMC 10 的 564 张概念卡**不在这套分级里**：它们没有 `difficulty` 字段，用的是自己那套
`level = core / advance / boundary`。两套刻度不要混着读。

## 四个等级：判据与真实例子

### 1 级：一条定义／公式／事实即可定案

**判据**：读完题就知道套哪一条，没有中间判断，也没有"先做 A 才能做 B"。

- `csa-007`（`(int)-4.9` 的值）：一条"强转向零截断"的规则定案，没有第二步。
- `calcbc-086`（极面积公式）：写出 `(1/2)∫r²dθ` 就结束——公式本身不好记，但它只是一条公式。
- `stats-scenario-019`（H0 真却被拒绝）：题干 94 个字、带 40 小时与 α=0.05，判据只有
  "第一类错误的定义"这一条，一步读出来。
- `csa-scenario-054`（翻倍步长的 `for` 循环执行次数）：判据只有"i 每趟翻倍、条件为 i <= 16"这一条，
  把 i 的取值逐趟列出（1、2、4、8、16）就定案，没有第二步换算。

### 2 级：两个标准步骤

**判据**：两步都是常规动作，先后顺序没有歧义（先算再读、先代入再解释）。

- `csa-001`（`7 / 2 + 7 % 2`）：整数除法得 3，再取余得 1，两步。
- `csa-004`（`"computer".substring(1,4)`）：定位端点取出子串，再按"含左不含右"读回来。
- `precalc-scenario-026`（`f(g(2)) − g(f(2))`）：两次复合分别求值再相减，标准两步。

### 3 级：三步以上，或两步但含真实陷阱

**判据**：步数到位；或者只有两步却踩到"条件必须先查""越界/重载/移位""常见错误干扰项"这类真陷阱。

- `csa-scenario-017`（`p(2)` 的打印顺序）：要按调用树走左递归→打印→右递归，三步以上。
- `csp-scenario-031`（500 行跑步记录求平均）：先统一单位、再处理缺失值、再去掉重复记录，
  三步且顺序不能反。
- `calcbc-scenario-037`（`∫_0^1 x³e^(x²)dx`）：换元与分部积分是两步，但"换元、分部各带一个 1/2"
  是真陷阱——干扰项 `1/4` 正是踩它踩出来的。

### 4 级：需要洞察或重构

**判据**：不能顺着最自然的路径算下去，得先看出某个结构性的事实，或者自己选方法。

- `calcbc-074`（`∫_{-1}^1 1/x² dx`）：按原函数算会得到 −2，必须看出 x=0 处的奇点、把积分拆开，
  才能判发散。
- `calcbc-127`（交错级数误差界求最小的 n）：要先把"误差小于 0.01"翻成 n 的严格不等式，并注意
  n=9 时的上界恰好等于 0.01，再求和。
- `csa-scenario-051`（子类同名静态字段 + `super()`）：得同时把握"同名静态字段遮蔽"与
  "父类构造体也会执行"两件事，四个计数才立得住。

## 判级时容易犯的错

**① 把"题干长／数值大"当成难。** `calcbc-scenario-026` 有 100 个字的分段定义，判 1 级，因为只需把
`(t²−9)/(t−3)` 约成 `t+3` 再代入；`csp-scenario-021` 有 109 个字的情境加上 Create task 报告的
措辞，判 1 级，因为只考"program purpose 与 input 该怎么写"这一条。反方向同样要小心：
`calcbc-050` 只有 `∫_1^∞ 1/x² dx？` 十来个字，却是 3 级——反常积分要先判敛、再求值。

**② 把"需要背公式"当成难。** rubric 的 1 级明写"一条公式即可定案"，所以 `calcbc-086`（极面积）、
`calcbc-068`（垫片体积）、`calcbc-040`（Newton 迭代公式）都是 1 级。背不下来是复习问题，
不是工作量问题。

**③ 把两道同构题判成不同级。** `csa-016` 与 `csa-017` 是同一段 `if`，只差一个 `else`，两道都是
2 级；`calcbc-050`（`1/x²` 收敛到 1）与 `calcbc-051`（`1/x` 发散）是同一副模具，两道都是 3 级。
反过来，长得像的一对也可能真的该不同级：`csa-scenario-013` 与 `csa-scenario-042` 的外壳都是
`public static int f(int n)`，但前者是树形递归、要把调用次数数出来（3 级），后者是每次折半的
单链递归（2 级）——同构与否看工作量，不看代码长相。

**④ 把"多问一句"当成多一步。** `calcbc-scenario-051` 有两问（先判断收敛、再求总质量），但裂项后
前 N 项和同时给出两个答案，它判 4 级是因为要想到部分分式裂项，不是因为问了两句；`calcbc-074`
只有一问，一样是 4 级。

**⑤ 把"没有分级"当成 1 级。** AMC 10 概念卡没有 `difficulty` 字段，打包格式给它写 0
（`scripts/pack-decks.mjs` 的 `packCard`）；`gradedDifficulty()` 只认正整数，
`availableDifficulties()` 因此不会渲染出 0 档。否则学生勾"难度 1"会捞到 564 张概念卡，
「我的」页的难度分布里也会多出一行假的 0 档。

## 谁在用这份分级

| 用到的地方 | 怎么用 |
|---|---|
| 练习页难度筛选（`src/app/(tabs)/study.tsx`） | 多选，`[3,4]` 是"只要 3 和 4"的并集；档位来自 `availableDifficulties()`，数据里没有的档不会出现 |
| 练习页难度排序 | `orderCards()` 按 1→4 或 4→1；没有分级的卡一律排在末尾，两个方向都一样 |
| 「我的」页题库概览（`src/app/(tabs)/profile.tsx`） | `summarizePool()` 数出每档题数与未分级题数，不变量是"总数 = 各档之和 + 未分级" |
| `npm run bank:stats` | 打印每个卡组的 `L1/L2/L3/L4` 计数与占比，是 README 那张表的唯一事实来源 |
| README「Difficulty, and what tagging it revealed」 | 两族的四列区间（各卡组占比的 min–max） |
| 门禁 `check-flashcards` | 见下一节 |

## 改级流程

改级只改一个文件，然后重跑生成链与门禁：

```bash
# 1) 只改这一处：content/subject-banks/difficulty.json 里某个卡组的 "题号": 级别
# 2) 重建卡片产物与打包产物（难度同时写进两边，门禁会做产物同步比对）
node scripts/build-subject-decks.js && node scripts/pack-decks.mjs
# 3) 门禁
node scripts/check-flashcards.mjs
```

门禁在这条路上检查四件事：

1. **齐全**：所有卡片都必须标 1–4，缺一题就直接失败——但"谁在管"要分清，`checkDifficulty` 的
   强制范围比"练习册与情境题"窄：它只对**非 `-scenario` 卡组**要求"必须有"（练习册缺一题即失败），
   情境题缺标注它不报；"值必须在 1–4 之内"与"单一级别不超九成"这两条对全部卡片一律生效。
   情境题的"一个都不能缺"由生成器管：`build-subject-decks.js` 在难度表缺失或某题没有 1–4 标注时
   直接 `throw`，再由 `checkDeckSourceSync` 把产物按当前源重建、逐字比对兜住（产物就是生成器的
   输出，改了 `difficulty.json` 不重跑生成链，这条比对就会红）。
2. **有区分度**：40 张及以上的卡组里，不能有单一级别占到九成以上，否则失败并打印
   `L1/L2/L3/L4` 计数——"整组都判成 2 级"不是省事，是没有分级。
   同一处的第二条是分布形状（`checkDifficultyShape`）：每个卡组的最难档（level 4）**一道都没有就失败**
   ——那意味着难度筛选在这个卡组里点不出最难档，而 `precalc-scenario` 曾经就是这样、门禁一直是绿的；
   **少于 3 道只警告不失败**（往 stderr 打一行），因为稀薄是当前题库可接受的现状，但必须每次跑门禁
   都看得见；两个阈值 `LEVEL4_EMPTY` 与 `LEVEL4_THIN` 是"最少可用的难档数量"这个工程判断，不是统计
   结论。摘要行里每次都带最难档总数与最薄的卡组。注意：把某个卡组的最难档改少，通常同时把第 3 条
   那张难度区间表里那一族的 level-4 min 拉低，于是 README 漂移也会一起红，两条要一起看。
3. **README 表同步**：难度区间表写的是各卡组占比的 min–max（四舍五入到整数百分比，
   见 `bank-stats.mjs` 的 `pct`；脚本头部注释里写的"向上取整"与实现不符，以实现为准）。
   一次改动可能只推动某个卡组一个百分点，却让区间端点变一格，这时表就红了：跑
   `npm run bank:stats -- --md=difficulty` 把新行粘回去。README 正文里那几句点名总数的句子
   由同一条检查比对，所以别顺手改那些数字。
4. **答案位置与台账不受影响**：轮转方案按题号冻结在 `content/subject-banks/rotation-plan.json`，
   某题是否轮转只看选项文本与简析里有没有字母引用，与难度无关；复核台账的哈希只用 front/back
   算（`hashOf`），所以改级不会让台账过期、不会挪动正确答案所在的字母，也不会动英文覆盖层的
   `src`。但产物必须重建：难度会写进 `src/data/subject-decks/*.ts` 与 `src/data/deck-pack.ts`。

改级不动题目正文，所以不需要 `sync-overlays.mjs`，也不需要更新
`scripts/flashcard-verification.json`；只有这次改动同时动了题干或简析时，才要走那两步。
